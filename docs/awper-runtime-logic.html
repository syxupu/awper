矛盾
All 锁关usercmd 管线恢复但 AI 也重新参与生成命令
反应式控制不是“确保只有一个 Bot”，而是“发现多余 Bot 后再删除”。
共享全局状态bot_quota、game mode、回合事件和其他插件都可能重新拥有 Bot 生命周期。
当前保护不足训练开始时写一次 cvar；训练中没有验证 cvar 是否被改回，也没有识别 Bot 的真正生成来源。
结构性风险
控制 Bot 依赖于“先让 Bot AI 自己运行”

All 锁会切断 usercmd 来源；关掉 All 锁才能注入移动，但同时恢复 AI。现在的方案本质上是借 AI 命令当载体，再局部覆盖它。

已证实故障
Bot 生命周期出现正反馈循环

旧日志中 slot 2–63 连续生成/删除不是偶发小问题，而是“插件删除 ↔ 外部补充”两个控制器互相打架。

语义错误
TargetSpeed 不是实际地速目标

代码只把它换算成 0–1 油门；没有用 CSV/实时速度做闭环修正。武器、加速度、地面和引擎上限才决定最终 units/s。

观测盲区
token 创建成功不代表命令真正落到 Pawn

当前部署未导出 movement apply 次数、最终 forward/left、命中 slot 等关键计数，因此托管层返回 true 后仍可能完全不动。

尚待实证
新锁切换版是否已经让速度非零

最后两份 CSV 都来自修复前；现在只能证明逻辑路径“可能通”，不能证明新版已运动。
